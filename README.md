# CalendarGen

CalendarGen converts a declarative TOML schedule into an iCalendar (`.ics`) file. It is designed for recurring weekly events, such as university lecture timetables. Define your term dates, time slots, and weekly classes once, and CalendarGen expands them into individual calendar events.

## Installation

Requires Python 3.12 or later.

Install via `pip`:

```sh
pip install calendargen
```

Alternatively, install it as a standalone tool using [uv](https://docs.astral.sh/uv/):

```sh
uv tool install calendargen
```

For development, install from a local clone in editable mode:

```sh
uv tool install --editable .
```

You can also run CalendarGen directly from this repository without installing it:

```sh
uv run calendargen init calendar.toml
uv run calendargen gen calendar.toml calendar.ics
```

## Usage

1. Create a starter schedule configuration:
   ```sh
   calendargen init calendar.toml
   ```
   > **Note:** `init` creates a new file and will not overwrite an existing file.

2. Edit `calendar.toml` with your schedule details.

3. Generate the ICS file:
   ```sh
   calendargen gen calendar.toml calendar.ics
   ```

4. Import the generated `calendar.ics` into your calendar application of choice (e.g., Google Calendar, Apple Calendar, or Outlook).

### Updating an imported schedule

If you need to make changes to your schedule:

1. Edit `calendar.toml` and re-run:
   ```sh
   calendargen gen calendar.toml calendar.ics
   ```
2. **Remove previously imported events** from your calendar application before importing the new file. Depending on your calendar application, re-importing an ICS file may produce duplicate events rather than replacing existing ones.
3. Import the newly generated ICS file.

> **Tip:** Setting a distinctive `description_footer` in your TOML config (e.g., `"Generated by CalendarGen (Fall 2026)"`) makes it easy to search for and delete all previously imported events in bulk.

## Schedule format

```toml
term_start = 2026-10-01
term_end = 2027-01-22
excluded_dates = [2026-11-03]
description_footer = "Generated by CalendarGen (Fall 2026)"

[time_slots]
"period 2" = { start = "10:30", end = "12:00" }

[[courses]]
title = "Applied Algebra"
weekday = "mon"
time_slot = "period 2"
location = "Room 201"
description = "Professor Smith"

[[day_overrides]]
date = 2026-10-15
use_weekday = "mon"
all_day_event_title = "Monday schedule"
```

### Configuration fields

- `term_start`, `term_end`: Inclusive start and end dates (YYYY-MM-DD) defining the academic term.
- `excluded_dates` *(optional)*: A list of dates on which all events are skipped (e.g., holidays, breaks).
- `description_footer` *(optional)*: Text appended (separated by a blank line) to each course description, and set as the description for events without one (including all-day override events). Omit it or set it to an empty string to leave descriptions unchanged. A distinctive footer makes it easy to search for and delete all generated events when updating schedules.
- `[time_slots]`: Named entries defining local start and end times (`HH:MM`). Courses refer to these slots by name via `time_slot`.
- `[[courses]]`: Defines weekly recurring events.
  - Required fields: `title`, `weekday` (`mon`, `tue`, `wed`, `thu`, `fri`, `sat`, or `sun`), and `time_slot`.
  - Optional fields: `location` and `description`.
- `[[day_overrides]]` *(optional)*: Applies another weekday's schedule to a specific date (e.g., October 15 follows the Monday schedule).
  - Required fields: `date` and `use_weekday`.
  - `all_day_event_title` *(optional)*: If specified, creates an additional all-day event on that date with this text as its title. Omit it for overrides that do not require an all-day event.
  - Overrides cannot share a date with `excluded_dates`.

### Validation and behavior

- **Strict validation:** Unknown field names in the schedule, time slots, courses, or day overrides are treated as errors.
- **Date ranges:** All dates specified in `excluded_dates` and `day_overrides` must fall within `term_start` and `term_end` (inclusive); out-of-range dates will raise an error.
- **Fail-safe generation:** When validation fails, CalendarGen will not create or replace the target ICS file.
- **Timezone:** Event times are generated using the local timezone of the machine running CalendarGen.
- **Discrete event expansion:** CalendarGen generates **a discrete, individual calendar event** for each occurrence throughout the term (rather than a recurring RRULE event).
